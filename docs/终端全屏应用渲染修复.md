# SSH 终端全屏应用（nano / vim / less / top）渲染修复

> 状态：已修复（2026-10-05）
> 涉及文件：`core/vt_screen.py`（新增）· `windows/remote_session/ansi_terminal.py`（重写渲染/输入层）·
> `windows/remote_session/ssh_terminal.py`（PTY 尺寸、日志、增量解码）· `windows/remote_session/__init__.py`（惰性导出）
> 回归门禁：`tests/test_vt_screen.py`（40 项）· `tests/test_ansi_terminal_render.py`（15 项）·
> `tools/smoke/smoke_ansi_terminal_tui.py`（22 项离屏断言）

## 一、现象（用户报告 + 截图）

项目 SSH 终端里进任何编辑器 / CLI 全屏界面就出现 UI 错乱。截图（远端 CentOS，`nano 2.3.1`
打开 `/etc/frp/frpc_proxies.toml`）里可见四个症状：

1. 文件 30 行正文**塌成 1 行**，只剩最后一行 `localIP = "192.168.1.202"` 加若干残留字符；
2. 每行都多出一个**字面字母 `B`**（`B  GNU nano 2.3.1…`、`B^X 离开…`）；
3. 底部光标方块位置显示成**字面 `&nbsp;`**；
4. status 行（`[ 已读取51 行 ]`）与第一行快捷键挤在**同一行**。

## 二、证据链（全部可复核，不是推测）

| # | 证据 | 说明 |
| --- | --- | --- |
| 1 | `logs/ssh_sessions/` 下那次会话的日志（会话记录器产物） | 原始字节里 nano 绘制期间**一个 `\n` 都没有**（实测 LF=19 / CR=61，且正文 30 行文本齐全，从 `serverAddr…` 到 `localIP = "192.168.1.202"`）。说明行与行之间只有 `\r` + 被记录器剥掉的 **CSI 定位序列** —— 正文不是远端没发，而是解析器丢了定位序列。 |
| 2 | 同一份日志里 `\x1b(B` 出现 **28 次** | `sgr0 = \E(B\E[m` 的痕迹：每次属性复位都发一次字符集设计符。旧解析器只吃掉 `\E(` 两个字节，第三个字节 `B` 直接落屏 —— 这就是症状 2。 |
| 3 | Git 自带 `xterm-256color` terminfo 解码 | `clear=\E[H\E[2J`、`smcup=\E[?1049h`、`csr=\E[%i%p1%d;%p2%dr`、`cup=\E[%i%p1%d;%p2%dH`、`vpa=\E[%i%p1%dd`、`il1=\E[L`、`dl1=\E[M`、`ech=\E[%p1%dX`、`dch1=\E[P`、`su/sd` **全部存在** → 远端 ncurses 确实在用这些序列，旧实现一个都不认。 |
| 4 | 前后 A/B（同一工作区，只把两个文件换回 `HEAD` 版） | `515 passed / 35 failed / 13 errors` → `546 passed / 35 failed / 13 errors`：+31 恰为新增单测，既有失败项**零变化**（隔离出本改动的净效果）。 |

## 三、根因

| 序列 / 机制 | 旧实现 | 造成的症状 |
| --- | --- | --- |
| `\E[<n>d`（VPA，纯纵向定位）、`\E[<n>E`（CNL） | 未知序列直接丢弃 | 30 行正文全写在光标当时所在的那一行上，互相覆盖 → 塌成 1 行、底行内容被后来的写覆盖（症状 1、4） |
| `\E(0` / `\E(B`（字符集设计符，3 字节） | 只吃 2 字节，第 3 字节当普通字符 | 每处属性复位漏一个 `B`（症状 2） |
| `\E)L`/`\E[M`（插行/删行）、`\E[<n>S/T`（滚屏）、`\E[t;br`（滚动区域） | 丢弃 | vim/less 滚动后屏幕内容整体错位 |
| `\E[<n>X`/`P`/`@`（擦/删/插字符） | 丢弃 | 编辑器局部更新（改一个字符）后该行错乱 |
| CSI 终止字节判定用 `isalpha()` | `\E[1P`/`\E[@`/`\E[2~` 永远等不到终止，吃满 64 字节 | 后续正文被整段吞掉 |
| 光标方块单元格转义 | 先转义再判断，`&nbsp;` 被二次转义成 `&amp;nbsp;` | 屏幕上显示字面 `&nbsp;`（症状 3） |
| 无固定网格 + PTY 尺寸写死 `120x40` | 行可无限长、可无限增长；远端按 120 列排版 | 控件与远端对"屏幕多大"的认知不一致 → 错位、撕裂 |

## 四、修复设计

### 4.1 分层（本轮最大的结构性收益）

```
core/vt_screen.py           零 Qt 依赖的屏幕语义（网格、光标、擦除、滚动区、备用屏幕、
                            属性、字符集、宽字符、回滚）—— 可用纯 pytest 离线验证
   ↑
windows/remote_session/ansi_terminal.py
                            控件层：键盘/鼠标 → key_input；屏幕网格 → HTML；尺寸 → grid_resized
   ↑
windows/remote_session/ssh_terminal.py
                            PTY 层：用控件网格开 shell、尺寸变化 resize_pty（去抖）、
                            增量 UTF-8 解码、会话日志
```

`windows/remote_session/__init__.py` 改为 PEP 562 惰性导出：以前任何
`windows.remote_session.*` 导入都会连带拉起 `qfluentwidgets`，导致缺该依赖的解释器下
连终端控件的单测都收集不了（每个测试只能自己"直载文件"绕行）。现在
`from windows.remote_session.ansi_terminal import ANSITerminalWidget` 不再受牵连。

### 4.2 网格与 PTY 尺寸契约（"错位"的技术核心）

* **权威 = 控件自身尺寸**（不是 `viewport()`：没显示过的控件 viewport 还停在 Qt 默认
  640×480，会让隐藏页签/恢复会话以错误尺寸开 PTY）；
* 行高用**真实 `QTextDocument` 实测**（Qt 富文本里无单位 `line-height` 按 font-size 倍数
  解释，与 `QFontMetricsF.lineSpacing()*1.3` 差约 5%，按后者算会多算一行 → 全屏应用
  最后一行被裁，而备用屏幕又关掉了滚动条，用户怎么滚都看不到）；
* 连接时先 `sync_grid(force=True)` 再 `invoke_shell(width=cols, height=rows)`，并把该尺寸
  记为"已同步尺寸"；尺寸变化经 120ms 去抖后才 `resize_pty`（拖动窗口逐像素发 SIGWINCH
  会让远端全屏应用反复重绘）。

### 4.3 宽字符（CJK / emoji 占两列）

宽字符写两格（第二格是续格哨兵 `\x00`），于是「格下标 == 列号」这条不变式继续成立，
光标、`EL/DCH/ICH/ECH`、渲染都不需要额外列换算；擦除/删除/插入遇到半个宽字符时整字处理；
宽字符放不进最后一列时按 xterm 语义先换行。回滚行的压缩表示保留哨兵，列结构不丢。

### 4.4 输入侧（编辑器"按键不对"的部分）

* 跟踪 `?1h`（DECCKM）：应用模式下方向键/Home/End 发 `\EOA..D`/`\EOH`/`\EOF`；
* 修饰键组合按 xterm 编码发 `\E[1;<mod>{A..D|H|F}`（Ctrl+方向键不再被吞）；
* `?2004h` 括号粘贴：`Ctrl+V` 用 `\E[200~ … \E[201~` 包起来（vim 多行粘贴不再逐行自动缩进）；
* 鼠标上报：`?1000/?1002/?1003` + `?1006`（SGR）→ 点击/拖动/滚轮发 `\E[<b;col;rowM/m`；
  本地选择与右键菜单改为 `Shift` 触发；
* `?1004h` 焦点上报 `\E[I`/`\E[O`。

### 4.5 其它

* 重渲染（`setHtml`）前后保存/恢复**选区与滚动位置**：否则远端每来一点输出就清掉选中，
  `Ctrl+C` 会从"复制"退化成给远端发 SIGINT；
* 会话日志：备用屏幕期间把 `\r` 归一化为 `\n`（全屏应用不靠 `\n` 换行，不归一化整屏日志
  会挤成一行；普通 shell 保留 `\r`，进度条靠它原地刷新）；
* `_strip_ansi` 补上字符集设计符与非字母终止字节的 CSI（旧正则会漏 `\E(B`、`\E[1P`）；
* reader 线程改 `codecs` 增量 UTF-8 解码（原来逐块 `decode` 会把被 recv 切断的中文变成乱码）。

## 八、维护提示

* `ansi_terminal.py` 里 CSS `line-height:1.3`（font-size 倍数）与 `_LINE_HEIGHT = 1.3`
  在代码注释里是**两个不同语义**，行数换算必须以 `_measure_line_height()` 实测为准，
  不要单方面改其中一个；
* 回滚行的压缩表示（`VTScreen._freeze/_thaw`）用 `\x00` 作宽字符续格哨兵，
  改格式时必须同时改这两处；
* `VTScreen` 是纯逻辑层：**任何 Qt 依赖都不许进来**（这是它能被离线单测的前提）。
