## 2. 三种实现方式对比

| 方案 | 说明 | 评价 |
| --- | --- | --- |
| **A. 官方 Python NetSDK wheel（推荐）** | `NetSDK-2.0.0.1-py3-none-win_amd64.whl`（纯 Python 封装 + 全套 win64 DLL），解压进 autowork，import NetSDK | ✅ 结构体/回调/错误码全部封装好；Python 3.13 兼容（已实测）；缺点=体积 +50MB 级、官方代码有 SyntaxWarning 噪音 |
| B. 裸 ctypes 只带 3 个 DLL | 仅 dhnetsdk.dll + libeay32 + ssleay32 | 体积最小，但结构体布局要自己维护——10-04 已踩 3 个坑（LoginEx2 签名/6 参回调/回调句柄），不建议长期 |
| C. 捆绑调用现成 exe | QProcess 启动 DevInit.exe 等 | ❌ 界面割裂、拿不到结构化数据、密码明文落盘、无法走 frp 隧道地址 |

**已验证证据**（方案 A，2026-10-06）：官方封装登录 114ms + 取流 5s 377KB 全通过，脚本
`tools/_scratch/dahua_netsdk_py_test.py`、SDK 解压于 `tools/_scratch/netsdk_py/`。
已知坑：**登录结构体必须显式 `dwSize=sizeof(...)`**，否则 0ms 秒败且报 "There is no such error code"。

## 3. autowork 挂载点（遵循现有架构）

- **UI**：`main_window/tool_hub.py:1509` `ToolHub(PivotPage)` 现有四子页（单杆视频/端口占用/上传清单/视频与日志批量整理），新增第 5 子页「相机工具」，`addPage(dahua_camera_work, "相机工具")` 即可。
- **线程**：沿用 QThread worker 模式（参考 `SingleVideoWork`）；⚠️ 项目既有契约——**worker 的 result 与 error 信号必须有双落点**（09-30 教训），SDK 回调（ctypes CFUNCTYPE）在 SDK 内部线程触发，必须经信号转发回 UI 线程，禁直接操作控件。
- **凭据**：相机账号走 `core/secrets.py` DPAPI 域（与上传凭据同机制），**不得**学 userinfo.ini 明文。
- **打包**：`AutoWork.spec` datas 增 `('vendor/dahua/NetSDK', 'NetSDK')`；运行时用 `sys._MEIPASS` 定位并 `os.add_dll_directory()`（10-04 脚本已验证此法有效）。可实测裁剪：纯登录/搜索/抓图/配置只需 dhnetsdk+dhconfigsdk+libeay32+ssleay32（约 40MB），play/RenderEngine/StreamConvertor 仅预览解码需要。

## 5. 风险与开放问题

1. **PyInstaller 兼容性未实测**：NetSDK 按相对路径加载 `Libs/win64`，打包后需验证 `_MEIPASS` 下的 DLL 定位（低风险，有 add_dll_directory 兜底）。
2. **单实例约束**：dhnetsdk 全局初始化（CLIENT_Init/Cleanup），autowork 进程内只能有一处持有；建议封装成单例模块 `core/dahua_sdk.py`，统一生命周期。
3. **32/64 位**：autowork 现打包为 64 位（dist 实测），与 win64 SDK 匹配 ✅；若未来切 32 位需换 SDK 包。
4. 预览解码若不想带 dhplay 全家桶，可把 RealPlay 原始码流（回调已是 H.264/H.265 裸流）交给现有 cv2/ffmpeg 流水线——autowork 单杆视频已有成熟 cv2 经验，P1 时二选一。
