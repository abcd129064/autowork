## 二、售后面板现状问题

### 2.1 布局

1. **设置页会被裁切**（最严重，功能不可达）：设置页没有 ScrollArea（`aftersale_panel.py:1392`），周期卡约 380px + MySQL 卡约 430px，合计超 800px，而窗口最小高度 520（`:1421`）。小窗口下底部卡片看不到也点不到。
2. **三页布局骨架不一致**：录入页是 ScrollArea+单卡片，记录页是裸 VBox 三段，设置页是裸 VBox 叠两卡。同一个面板三种骨架。
3. **候选列表引起跳动**：桌号候选 `QListWidget` 固定高 132 作为表单的一行（`:302-312`），出现/隐藏时下方所有字段整体位移 132px。
4. **标签列错位**：「是否解决/解决人」两组用 `form.addRow(row)` 塞内联 QLabel（`:351`、`:382`），与上方「类型/球房」的标签列对不齐；组内间距靠 `addSpacing(16)` 硬编码。

### 2.2 交互流程

5. **编辑/删除不可发现**：只在右键菜单和双击里（`:919`、`:1123`），工具栏没有任何可见入口。第一次用的人找不到。
6. **多选与删除能力不匹配**：表格开了 ExtendedSelection 多选（`:911`），但删除只处理 `rows[0]`（`:1117`）。选了五条删一条，行为与预期相反。
7. **「标记已解决」三步走**：右键 → 弹完整编辑表单 → 保存（`:1161-1170`）。这是售后场景最高频的动作，路径却最长。
8. **校验只有一条汇总提示**：`validate()` 五项必填（`:550-563`），失败弹一条 InfoBar「无法提交」，不指出是哪个字段、不滚动到缺失项。
9. **必填星号与校验不一致**：桌号、地区必填但标签无 `*`；「发生时间 *」标了星号却从不校验（默认当日）。
10. **导入图标误导**：导入 Excel 用 `FluentIcon.ADD`（`:883`），ADD 语义是"新增"。
11. **筛选无重置**；桌号跳转复用关键词框做预筛选（`:1004-1010`），用户察觉不到自己处于过滤态。

### 2.3 视觉一致性 / 状态展示

12. **表头截断**：「是否我们主动发起」「是否是我们的问题」各 8 个中文字约 104px，列宽只给 76（`:735-736`），必然省略号。文件注释声称按 13px/字核算过，这里和核算结果对不上。
13. **13 列合计约 1457px**，最小窗口宽 900 时横向滚动严重；发生原因/解决方案/设备编码不在列里，只能逐个开编辑弹窗看。
14. **状态词汇三套并存**：表格单元格「是/否」、筛选器「已解决/未解决」、统计行「已解决/未解决」。已解决仅靠前景色+「是」表达。
15. **统计无层级**：底部一行小字「共 N 条 · 已解决 X · 未解决 Y」（`:933`），和数据源标签、周期标签混排同一行。
16. **异步加载零反馈**：查询期间表格留着旧数据，无 loading、无禁用（`:1048-1060`），用户分不清"查询中"和"无数据"。
17. **无空状态**：0 条时表格空白加一行「共 0 条」。
18. **查询失败只写底部小字**（`:1079-1081`），不弹 InfoBar，和其他错误处理路径不一致。
19. **数据源指示滞后**：只在读写回调后刷新（`:1068`、`:1081`），设置页切换后端回到记录页时标签可能还是旧值。
20. **编辑弹窗 560 宽装不下表单**：表单内「类型 320+间隔+日期组」一行约 610px（`:266-277`），560 宽下被压缩。录入页和编辑弹窗复用同一个 `AftersaleForm`（这是好设计），但容器尺寸没跟着表单走。

## 三、对比分析与推荐方案

分三步走，按"先修不可用、再降操作成本、最后统一视觉"排序。

### 方案 A：修复不可用问题（建议立即做）

| 现状 | 改为 | 涉及位置 |
|---|---|---|
| 设置页小窗口裁切 | 设置页套 ScrollArea（与录入页同骨架） | `:1392` |
| 查询无反馈 | `_load` 开始时表格上叠半透明 loading 指示，或工具栏刷新按钮转 `FluentIcon.SYNC` 旋转 | `:1048` |
| 0 条空白 | 空状态占位（`FluentIcon.LIBRARY` 灰图标 + "当前周期暂无记录" + 引导文案） | `:1069` |
| 查询失败小字 | 失败弹 warning InfoBar + 状态栏保留错误详情 | `:1079` |
| 表头截断 | 两个"是否"列加宽到 110，或表头改短词（"我方发起"/"我方责任"）+ tooltip 全称 | `:726-740` |
| 编辑弹窗压缩 | 最小宽 560 → 640，与表单实际宽度匹配 | `:701` |

预期效果：消除"功能点不到、状态看不见"两类硬伤。全部是局部改动，不动数据结构。

### 方案 B：缩短高频操作路径

1. **「标记已解决」一键化**：右键菜单直接调 `_update_record(resolved="是")`，不再弹完整表单。高频动作从 3 步降到 1 步。
2. **批量删除**：多选后确认弹窗列出条数，循环删除。让多选能力真正生效。
3. **行内操作可见化**：表格行尾加一列「操作」（编辑/删除图标按钮），或选中行时工具栏浮现操作按钮。右键菜单保留作为快捷方式，不再是唯一入口。
4. **字段级校验**：`validate()` 返回缺失字段列表，对应控件标红 + InfoBar 指明第一个缺失项 + 滚动定位。
5. **必填星号对齐校验规则**：桌号、地区补 `*`；「发生时间」去掉 `*`（它有默认值，永远不会为空）。
6. **筛选重置 + 预筛选可见**：筛选区加「重置」按钮；从主窗口带桌号跳转进来时，关键词框显示可移除的过滤标记（如 `[桌号: A12 ✕]`）。
7. **导入图标**：`FluentIcon.ADD` → `FluentIcon.DOWNLOAD`（或 `IMPORT` 语义更准的图标），导出对应用 `UPLOAD`/`SHARE`。

预期效果：日常最高频的"登记 → 跟进 → 标记已解决"链路步数减半，误操作（多选删除）消除。

### 方案 C：信息层级与视觉统一

1. **统计升级为指标卡**：底部小字改为顶部三张指标卡（总数 / 未解决 / 已解决），未解决用 `SEMANTIC["danger"]` 强调——售后场景里未解决才是需要被看见的数字。数据源标签移到指标卡行右侧或工具栏，不再和统计混排。
2. **状态词汇统一**：全面板统一「已解决 / 未解决」，表格单元格不再显示「是/否」。已解决可加浅色底 + 图标圆点，不只靠前景色（色盲友好）。
3. **三页统一骨架**：统一为「页内边距 24/20、间距 14、内容套 CardWidget、超长套 ScrollArea」，录入页现状即模板，记录页和设置页向它对齐。
4. **候选列表改浮层**：桌号候选从"占一行的固定控件"改为贴着桌号输入框下方的浮层（`QCompleter` 或定位弹出的 `QListWidget`），出现/消失不再推挤表单。
5. **长文本列收纳**：发生原因/解决方案不进表格列，改为行悬停 tooltip 或点击行展开详情抽屉，缓解 1457px 横向滚动。
6. **间距走令牌**：页内边距/间距改用 `SPACE` 令牌，控件高度统一 33（按钮现在 36，输入 33）。

预期效果：面板从"三页三种长相"收敛为一套语言；关键数字一眼可见。

### 实施顺序建议

A → B → C。A 全部是低风险局部修复，可单独一轮完成；B 涉及交互逻辑，建议配合手工回归清单（登记/编辑/删除/导入导出/标记已解决各走一遍）；C 是视觉重构，建议在 A/B 稳定后整页改版一次做完，避免反复改同一批代码。

### 验收口径

- 窗口缩到最小尺寸 900×520，三个页面所有功能点可见可点
- 查询/提交全程有可见状态反馈；0 条有占位；失败有 InfoBar
- 「标记已解决」单步完成；多选删除条数与选择一致
- 表头无截断；全面板状态词汇仅「已解决/未解决」一套
- 84 项回归测试保持全绿
