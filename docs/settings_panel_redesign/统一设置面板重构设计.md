## 1. 背景与问题定位

用户反馈"重构后的设置面板缺了路径配置、frp 配置、模型配置、日志高亮"。

排查结论：**不是某个 tab 没写，而是迁移没做完**——这四类配置此前都实现在**弹窗式 `SettingsDialog`** 里，而 Hub 重构只把「外观 / 性能 / 工具 / 数据库 / 面板设置」5 大组建好了，**没有把弹窗里的 7 个配置域整体迁入**。

## 5. 控件行为规格

| 控件 | 触发时机 | 存储调用 | 注意 |
|---|---|---|---|
| 路径输入 | `editingFinished` + 浏览按钮 | `set(key, text)` | 浏览用 `QFileDialog`，起始目录取当前值；dir/file 按字段区分 |
| 文本 / 数字 | `editingFinished` | `set(key, text)` | 端口类走 `_safe_int(v, default)` 兜底 |
| 密码类 | `editingFinished` | `set(key, text)` | 回显明文（门面已解密），落盘自动 DPAPI |
| 开关 | `checkedChanged` | `set(key, bool)` | **先 `setChecked` 再 `connect`**，避免初始化误写 |
| 下拉 / SpinBox | `currentIndexChanged` / `valueChanged` | `set(key, data)` | 复用 `make_combo` / `make_spinbox` |
| FRPC | 三个控件任一变更 | `get` 副本 → 改 → `set` 回 | 嵌套 dict |
| AI Key | 厂商切换 / Key 变更 | `get` 副本 → 改 → `set` 回 | `ai_api_keys[vendor]`，清空即 `pop` |
| 日志规则 | 添加 / 编辑 / 删除后 | `set("log_highlight_rules", list)` | 数组整体写 + 立即重编译 |
| MysqlSyncCard | 卡内保存按钮 | 卡片自带 `_collect_cfg` | 补信号触发 backend 缓存失效 |

## 6. 保存链路设计

```
[内联控件编辑] → [app_settings.set(key, value)] → [config/*.json 分域落盘]
                                                          ↓
                                              按 key 触发后处理钩子
```

统一入口：

```python
def _save_pending(self, key, value):
    app_settings.set(key, value)      # 按 KEY_DOMAIN 自动路由
    self._run_post_hooks(key)         # 按 key 触发后处理
```

### 后处理钩子（现有弹窗逻辑必须原样迁移）

来源：`main_window/ui_mixin.py:1547-1569`（`_on_open_settings` 保存后的处理段）

| 配置键 | 后处理 |
|---|---|
| 路径类（`exe_dir` 等） | `_load_paths()` 重载路径 |
| `mysql_sync` | `backend.invalidate_mysql_settings_cache()` |
| `log_highlight_rules` | `self._log_rules = _compile_log_rules(...)` 重编译（不刷新则旧规则仍生效） |
| `font_size` / `font_family` | `_apply_global_font()` |
| `dpi_scale` | 提示"缩放已修改，重启后生效" |

### 加密下沉

`credentials.json` / `database.json` 两域由门面自动处理：写盘前 `encrypt_settings`、读盘后 `decrypt_settings`，**UI 只接触明文**，控件层无需任何加解密代码。

## 7. 三个待拍板决策 ⚠️

截图的 7 个分页里，现有 Hub 的「性能」「工具」「面板设置」三组没有落点，且「数据库」组与「SQL 同步」分页撞车。

### ① 数据库与接口 —— AdminSettingsPage 撞车

现有 Hub「数据库」组 = `AdminSettingsPage(embedded=True)`，内含**数据源 / 接口1·2 账号 / 收集上传卡 / MySQL 卡**。其中"收集上传"与第 4 分页重复，"MySQL"与第 3 分页重复。

**建议**：数据源与接口账号并入第 3 分页，改名「数据库与接口」；上传卡删除（第 4 分页已覆盖）。

### ② 性能组没有落点

现有「性能」组（亚克力 / 动画 / 表格平滑 + 4 个面板级覆盖）在 7 分页里无对应页。

**建议**：并入第 7 分页底部，改名「外观与性能」。

### ③ 工具组、面板设置组不是配置项

- 「工具」= 6 个操作入口按钮（修改快捷键 / 上传清单 / 连接诊断 / 单杆视频 / 端口占用 / 批量整理）
- 「面板设置」= 售后周期 + 跑视频署名

两者都是"操作/业务面板设置"，硬塞进 7 分页会破坏一致性。

**建议**：另开两个分页「工具」「面板设置」，即最终 **9 分页**。

> 备选：严格 7 分页 —— 工具收进「外观与性能」页顶部，面板设置收进「数据库与接口」页底部。

## 9. 验收清单

1. **切换**：7 个分页切换不卡顿，每页只构建一次（懒加载保留）。
2. **落盘**：每个控件编辑后即时写入对应 `config/{domain}.json`；重启后回显一致。
3. **加密**：`ssh_pass` / `ai_api_keys` / `upload_pass` / `frpc_server.auth_token` / `mysql_sync.password` 在文件中以 `enc:` 前缀存在；UI 回显明文。
4. **日志高亮**：改一条规则（例：把「add」颜色由橙改绿）→ 日志窗口**立即**按新规则着色（`_log_rules` 必须重编译）。
5. **SQL**：MySQL 配置保存后 `backend` 按新配置重建连接。
6. **回归**：`pytest tests/ -q` 全通过（基线 260，含 `test_app_settings` 10 用例）。
7. **GUI 冒烟**：`QT_QPA_PLATFORM=offscreen` 下每页各切一次并回显（`os._exit(0)` 规避退出段错误，以 exit code 为准）。
