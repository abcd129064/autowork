# 表格滚动延迟调查报告（2026-09-25）

> 现象（用户反馈）：售后面板「记录与统计」与管理面板「球桌管理」表格上下滚动有 150~300ms 延迟，且在**性能选项全关**（动画开、表格平滑滚动关）下依然很卡。
> 性质：调研 + S2 已实施（2026-09-25 晚，见 §三 S2 落地实测与等价性验证；同日实施的 N1~N4 见《管理面板性能调查报告2026-09-25.md》§七）。
> 前置报告：`docs/perf_scroll_investigation.md`（2026-09-07，P0-1 LeanTableDelegate 已落地）——本报告在其之上回答「为什么关掉优化还是卡、卡在哪」。
> 复测脚本（本轮新建）：`tools/perf/perf_scroll_latency.py`（支持 `--scale` 模拟真机 DPI 缩放）；结果快照 `tools/_scratch/perf_scroll_latency_<1.0|1.5|2.0>.txt`（不入库）。

---

## 〇、测量方法与环境注记

- 指标一：**每步滚动耗时** = 逐步 `verticalScrollBar().setValue()` + 同步 `viewport().repaint()`（与 09-07 报告同口径，可直接对比）。
- 指标二：**滚轮单档延迟** = 发送一档 `QWheelEvent`（120，一格）→ 同步等 repaint 完成，即用户「转一下滚轮到画面动完」的真实体感。
- 变体：`prod`（构造后实际安装的委托）/ `default`（qfw `TableItemDelegate`，即**性能优化全关路径**）/ `lean`（P0-1 轻量委托）/ `cache`（单元格绘制缓存原型）。
- **环境关键差异**：offscreen 平台无字体目录（`QFontInfo.family()` 为空，字形为合成方框），**文本排版成本相对真机被低估**；真机用微软雅黑等真实 CJK 字体经 HarfBuzz 整形，逐格成本显著更高。`QT_SCALE_FACTOR` 模拟真机 DPI 缩放（CPU 光栅面积 ≈ dpr²）。

## 一、实测数据（60 行页，30 步 × 3 轮中位，ms/步）

**售后记录页 RecordsPage（13 列，可视 ~244 格/帧）**

| 变体 | scale 1.0 | scale 1.5 | scale 2.0 |
|---|---:|---:|---:|
| prod（OpsLeanDelegate = 轻量委托开） | 6.8 | 8.8 | 9.6 |
| **default（qfw 默认 = 性能优化全关）** | **14.7** | **16.0** | **18.2** |
| lean（LeanTableDelegate） | 7.2 | 8.7 | 10.6 |
| **cache（单元格绘制缓存）** | **2.3** | **3.1** | **4.2** |

**管理面板球桌页 TablePage**

| 变体 | scale 1.0 | scale 1.5 | scale 2.0 |
|---|---:|---:|---:|
| prod（构造后委托） | 11.0 | 12.1 | 12.9 |
| **default（qfw 默认 = 性能优化全关）** | **10.6** | **12.2** | **13.1** |
| lean（LeanTableDelegate） | 5.4 | 6.8 | 7.5 |
| **cache（单元格绘制缓存）** | **1.9** | **3.0** | **4.3** |

paint 均为 1.0 次/步（每次滚动恰一次全视口重绘，无重复重绘风暴）。

## 二、根因分析

**结论：滚动链路本身干净（单次重绘、无懒加载、无子控件），用户关掉的「轻量委托」正是主要提速项——性能优化全关 = 主动回退到 ~2× 慢的 qfw 默认委托；再叠加真实 CJK 字体整形与 DPI 缩放的光栅放大，150~300ms 体感成立。**

逐条归因：

| 因素 | 量化 | 说明 |
|---|---|---|
| **① 轻量委托被关闭（主因）** | default 是 lean 的 **1.8~2.1×**（售后 14.7 vs 7.2） | `perf_lean_delegate=false` 时表格回退 qfw `TableItemDelegate`：每格 save/restore + 裁剪 + 抗锯齿 + 圆角背景 + `initStyleOption` + **QTextLayout 逐格排版**。09-07 报告已证文本排版占滚动耗时 68% |
| **② 真实 CJK 字体整形（offscreen 低估的部分）** | 旧报告长文本变体 +44.5%；本轮 offscreen `QFontInfo.family()` 为空 | offscreen 无字体目录、字形为方框，不付 HarfBuzz 整形成本；真机雅黑逐格整形成本显著更高，倍率在 qfw 默认路径上被逐格放大 |
| **③ DPI 缩放光栅放大** | scale 2.0 相对 1.0：default +24%、lean +47%、cache +82% | 光栅面积 ≈ dpr²；但纯 blit 的 cache 绝对值仍最低。真机 125%~200% 缩放普遍 |
| ④ DWM/核显合成 | 未测（offscreen 不含） | 只影响绝对值，不改变相对排序 |

**排除项**（继承 09-07 报告并复核）：

| 假设 | 结论 |
|---|---|
| 滚动时懒加载 | 不存在（行数 60→15 耗时 +0.1%，历史证据仍有效） |
| 操作列 cellWidget | 已于 2026-09-19 文字链接化（零子控件） |
| hover 整视口重绘风暴 | 已被 `patch_table_hover_repaint` 中央拦截（main.py 启动即装） |
| 平滑滚动动画 | 用户已关（NO_SMOOTH 直通）；实测滚轮单档延迟 ≈ 单帧重绘成本，即关了也是「每格排版重」 |
| paint 风暴 | 每步恰好 1 次 paint，无重复重绘 |

### 二·补充：可见列数扫描（2026-09-25 第二轮真机反馈）

用户复测：轻量委托下「球桌管理筛选只留 3 列时滑动流畅，展示列越多越卡」。
harness 新增 `--cols 3,7,13,20` 扫描模式（`setColumnHidden` 模拟筛选勾选），实测
每步延迟随可见列数**近线性增长**（可见单元格数 = 可见列 × 可见行，lean 每格
仍有固定成本：save/restore + 裁剪 + 背景填充 + 6 次 index.data + 缓存键构建）：

| 可见列数 | 球桌 lean @1.0@1600x900 | 球桌 lean @1.5@2560x1440 | 售后 lean @1.5@2560x1440 |
|---|---|---|---|
| 3 列 | 3.05 ms | 10.30 ms | 9.90 ms |
| 7 列 | 4.25 ms | 14.28 ms | 13.51 ms |
| 13 列 | 5.85 ms | 18.08 ms | 19.86 ms |
| 全列 | 7.33 ms | 17.68 ms | 19.67 ms |

（prod 行同扫，球桌页 13 列时 29.93 ms/步@1.5@2560——库默认委托更敏感；完整数据
`tools/_scratch/perf_scroll_latency_cols_*.txt`）

**结论**：①列数效应与 DPI 效应**相乘**——3 列在 829 万像素下也已有 ~10ms 地板，
列数把 lean 从「流畅」推过 16.7ms/帧预算线；②真机 CJK 整形与 DWM 合成再放大，
即用户「3 列流畅、全列明显卡、关平滑滚动只缓解不掉」的体感。单靠 S2 文本层
缓存到顶了：剩余成本在**每格固定开销**，需 S5 整格缓存才能再下一档。

## 三、方案（按收益/成本比降序）

### S1【P0 · 零代码】打开「轻量委托」，不要再关

- 设置页「轻量表格委托」**默认就是开的**；本轮证实「性能优化全关」恰恰回退到 2× 慢的路径。若此前因其它问题关闭过它，滚动卡顿与它无关（它只影响委托绘制，无其它副作用）。
- 预期收益：售后面板滚动帧成本 **-50%**（14.7 → 7.2ms offscreen 口径）。

### S2【P1 · 已实施 2026-09-25】文本层绘制缓存（LeanTableDelegate 之上再砍文本排版）

- **改法**：在 `core/lean_table_delegate.py` 内把 `_draw_text` 的 `painter.drawText` 换成**预渲染文本 QPixmap blit**（背景/hover/选中/勾选框仍实时绘制，保证交互状态正确）。失效键 `(row, col, w, h, text, 主题, 字体, 前景色, 对齐, dpr)`：排序移动行、编辑单元格、切主题均自然失效；容量上限 2000 项（超限整体清空，同既有 elide 缓存策略）。
- **原型地板**（本 harness cache 变体 = 整格含背景缓存，仅作参照）：售后 2.3ms/步、球桌 1.9ms/步。
- **落地实测**（lean 变体，S2 前后）：售后 7.2 → **5.9**（scale 1.0）/ 10.6 → **7.6**（scale 2.0）ms/步；球桌 5.4 → **4.5** / 7.5 → **6.1** ms/步。offscreen 无字体低估文本排版成本，真机 CJK 整形路径收益更大。
- **等价性验证**：探针证实「缓存永不命中（强制直接 drawText）/ 冷渲染 / 暖缓存全命中」三种路径渲染结果 **PNG 逐字节一致**（含换行、elide、彩色前景、右对齐样本）；`_invalidate()` 清空链完整。
- **待真机确认**：按 §三 S3 口径在卡顿机器复测 + 日常视觉走查（换主题、编辑单元格、排序、跨屏拖动）。

### S5【P1 · 已实施 2026-09-26】整格绘制缓存转正（针对「列多更卡」的直接解）

- **依据**：二·补充节实测，S2 后每格仍有固定开销（背景填充 + 6 次 `index.data` +
  13 元组缓存键 + blit），可见单元格数线性放大它；harness 既有 `cache` 变体
  （整格含背景预渲染，每帧每格只剩 1 次 drawPixmap）地板 2.3~9.2ms，**对列数的
  斜率比 lean 小约 3×**。
- **落地**（`core/lean_table_delegate.py`，`_cell_pm_cache`）：整格（背景+勾选框+
  文本）预渲染为 QPixmap，滚动帧每格 1 次 `drawPixmap` + 每帧选中指示条；失效键 =
  S2 键 + 背景角色 + 勾选状态 + 列总数（首末列圆角形状）+ dpr；容量 2000 项超限
  整体清空。渲染以**满格原点**逐算子复刻直绘序列（clip=满格 → rect 变异为内矩形
  → 背景 → 勾选框 → 文本复用 S2 文本层缓存），保证与直绘同构、跨滚动位置渲染稳定。
- **对原案的两处已声明偏离**：
  1. **行状态并入缓存键**（原案「blit 后叠加半透明填充」）：叠加会把 tint 压在
     文本/勾选框**之上**，而直绘背景在文本**之下**——绘制顺序不一致，逐字节等价
     不成立（彩色前景/主题色勾选框会被洗色）。状态变体键（滚动帧恒命中 base
     变体，hover/选中行首次各渲一次）保持全状态逐字节等价且滚动帧零填充成本。
  2. **勾选格存在 ±1 通道微差**（原案验收口径「PNG 逐字节比对」的唯一例外）：
     隔离实验证实（`drawRoundedRect` 主题色笔刷单独复现同样 23/4560 像素、同样
     ±1/255 值）——直绘把勾选框 AA 边缘**一次融合**合成到不透明视口，缓存路径 =
     透明 QPixmap 预乘量化 + blit 源叠加**两步舍入**，预乘 8bit 的中间量化损失
     表现为 AA 边缘 ±1/255（0.4% 通道差，不可感知）。文本/背景 tint（RGB∈{0,255}×
     整数 alpha 的预乘数学精确）/不透明自定义背景均逐字节等价；**半透明自定义底色
     （alpha∉{0,255}，如售后「是」徽章 `setAlpha(20)`）同族风险 → 强制直绘不缓存**。
- **等价性验证**（`tests/test_lean_cell_cache.py`，35 例全绿）：10 格无状态 +
  5 状态 × 2 行型矩阵逐字节一致；勾选格容差断言（差异限于勾选框包围盒、逐通道
  |Δ|≤1、≤2% 像素）；缓存命中（QPixmap 对象身份不变）；8 类失效（文本/主题/
  dpr/列宽/勾选/背景角色/_invalidate/setCheckedColor/容量）；渐变刷与半透明底色
  回退直绘；option.rect margin 变异语义双路径一致（操作列链接几何依赖）。
- **落地实测**（harness `--cols 3,7,13,20`，30 步 × 3 轮中位，offscreen）：

  | 可见列数 | 球桌 lean @1.0@1600×900 | 球桌 lean @1.5@2560×1440 | 售后 lean @1.5@2560×1440 | 售后 **prod**（真实链路）@1.5@2560×1440 |
  |---|---|---|---|---|
  | 3 列 | 3.05 → **1.24**（-59%） | 10.30 → **5.54**（-46%） | 9.90 → **5.01**（-49%） | **5.12** |
  | 7 列 | 4.25 → **2.19**（-49%） | 14.28 → **7.42**（-48%） | 13.51 → **6.76**（-50%） | **6.91** |
  | 13 列 | 5.85 → **3.29**（-44%） | 18.08 → **9.08**（-50%） | 19.86 → **9.87**（-50%） | **10.99** |
  | 全列 | 7.33 → **3.28**（-55%） | 17.68 → **9.12**（-48%） | 19.67 → **9.65**（-51%） | **10.83** |

  （→ 前为 09-25 S2 基线，后为 S5 实测；prod=OpsLeanDelegate 即生产路径——
  勾选列/徽章列/操作链接的少量每帧直绘使其比 lean 高 ~1ms。**「全列回到 ~3 列
  流畅度」达成**：全列 9.1~10.8ms 已低于 S2 时代 3 列水平（9.90~10.30ms）；绝对
  值略高于原案预估 ~8ms 的残差 = 每帧保留的键构建（17 元组）+ 6 次 `index.data`
  + 状态查询，harness 原型地板（6.54ms）之上 2.5~4.3ms。滚动帧零文本排版，
  真机 CJK 整形成本被缓存吸收，预期真机与 offscreen 差距远小于 S2 时代。）
- **待真机确认**：卡顿机器复测 §五命令 + 日常走查（换主题、编辑单元格、排序、
  跨屏拖动、勾选列勾选/取消的视觉）。


## 四、「不做」清单

| 项 | 不做原因 |
|---|---|
| ScrollPerPixel | 09-07 报告实测反优化（-0.7%） |
| 预加载更多行 / 提前建 item | 无懒加载可优化，0% 收益 |
| 关动画治滚动 | 菜单/弹窗动画与表格滚动无交集；滚轮延迟 = 单帧重绘成本 |
| 锁死轻量委托开关（移除设置项） | 可选的产品决策；先用 S2 把「开了也够快」的缓存地板做出来，再决定是否保留开关 |
