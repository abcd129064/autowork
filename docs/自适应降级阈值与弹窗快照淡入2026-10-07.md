## 二、item3：自适应降级阈值

### 2.1 为什么不能再写死 600 万

原阈值是**一台真机上的经验值**（55 寸外接 4K@150% = 829 万物理像素时弹窗动画单帧
48.4ms）。同一份代码在快机上会把本可流畅的机器推早降级，在更慢的机器上又拦不住。
降级判定的本质是「**一帧的合成/光栅成本是否超过交互预算**」，而这取决于机器，
不是分辨率。

### 2.2 标定工作量（可复跑）

选一把**与弹窗放大路径同机理**的尺子：把一张 1414×1414 ARGB32（alpha=160）的位图
以 `setOpacity(0.5)` + `drawPixmap` 混到同尺寸目标图上 —— 即「半透明大位图的合成+光栅」，
与弹窗整窗 opacity/卡片 opacity 的成本构成一致。热身 2 次后取 3 轮中位。

| 工作量 | 2.0M 像素 | 4.0M | 8.29M |
| --- | --- | --- | --- |
| W1 半透明混合（**基准尺**） | 0.596ms（0.298 ms/百万像素） | 0.900ms（0.225） | 2.001ms（0.241） |
| W1b 不透明 drawPixmap | 0.136 | 0.199 | — |
| W3 `QImage.scaled(Smooth)` | 0.231（2M） | — | — |

**基准速率 = W1 @2.0M 的 0.298 ms/百万像素**。选 2.0M 而不是更大的图，是因为它就在
弹窗卡片量级上（近线性区），且不需要把大图常驻内存。本机（offscreen scale 1.5）复测：
整窗 `grab()` 中位 11.338ms、`render()` 5.649ms @8.29M 物理像素。

### 2.3 换算与夹取

```
rate   = measure_raster_rate_ms_per_mpx()          # 本机中位速率
ratio  = clamp(0.298 / rate, 0.25, 4.0)            # 机器倍率
limit  = clamp(6_000_000 * ratio, 1_200_000, 24_000_000)   # 物理像素
```

- 基准机 rate≈0.298 → ratio≈1.00 → **阈值仍 600 万（零回归）**；
- 慢一倍 → 300 万（更早降级）；快一倍 → 1200 万（更晚降级）；
- 倍率夹在 [0.25, 4.0]：单次标定噪声（首个计时器抖动、电源模式切换）不该把阈值
  推到离谱区间；阈值本身夹在 [120 万, 2400 万]，保证任何机器上都「有降级点」。

### 2.4 生效优先级与失败安全

`get_effective_degrade_pixels()` 的顺序是**显式配置 > 自适应 > 静态默认**：

1. 用户在配置里写了 `perf_dpi_degrade_pixels`（含 0=关闭）→ 用它，自适应不参与；
2. 否则 `perf_dpi_degrade_adaptive` 为真且标定成功 → 用自适应值；
3. 标定失败（无 QApplication / pixmap 构造失败 / 异常）→ 静态 600 万，且
   `_raster_rate_failed` 置位**不重试**（避免每帧都去踩一次失败路径）。

`get_dpi_degrade_pixels()` 冷启动时会先读一次配置并把「配置里真的写了 key」记为
`_dpi_degrade_pixels_explicit` —— 这一步必须**在判 explicit 之前**发生，否则显式配置
永远被自适应盖掉（首版就是这么错的，被 `tests/test_perf_auto_degrade.py` 抓出）。
`bigscreen` 模式优先于以上一切。

### 2.5 可观测

`degrade_diagnostics_text()` 一行中文，直接显示在「性能选项」对话框顶部与
设置中心 → 渲染加速状态：

```
自动降级阈值：600 万像素（自适应，本机 0.298 ms/百万像素，倍率 1.00×）；大屏性能模式开启（强制降级）
```

配置显式指定时显示「配置指定」；关闭时显示「已关闭」；标定失败显示「静态默认」。

## 三、item2：快照淡入

### 3.1 动机

2026-09-25 版对超阈值机器的处理是「跳过动画直显」。功能上正确，但大屏用户从此
看不到任何过渡（用户描述为「弹窗像被拍上去」）。快照淡入要的是：**保留动画，
但把每帧成本从「整窗 opacity effect」降到「贴一张浅位图」**。

### 3.2 机制

1. `showEvent` 里先把卡片 `setVisible(False)`，`QTimer.singleShot(0, ...)` 到事件循环里
   构建快照（**构建期临时隐遮罩、显卡片**，做完复原）；
2. `_build_dialog_snapshot(dlg, card, margin=72)`：区域 = 卡片四边各外扩 72px
   （阴影 blur 60 + offset y10）并与对话框求交，按 `devicePixelRatioF()` 建 pixmap，
   只带 `RenderFlag.DrawChildren` 渲染 —— **不带 `DrawWindowBackground`**，否则半透明
   对话框会被填成不透明黑；
3. 中心像素 `qAlpha < 250` → 判定「卡片不是不透明体」→ 返回 `(None, None)`，
   回退直显（失败安全：宁可没动画，也不给用户一张透明/黑卡片）；
4. `_SnapshotOverlay(QWidget)`：贴图 + `WA_TransparentForMouseEvents` +
   `WA_NoSystemBackground`，`paintEvent` 里 `p.setOpacity(t); p.drawPixmap(...)`。
   **它自己不挂任何 QGraphicsEffect** —— 用 painter 的 opacity 而不是 effect，
   成本从「整窗离屏合成」变成「一次带 alpha 的位图贴图」；
5. `QVariantAnimation` 0→1 / 200ms / InSine 驱动 opacity；每帧比对
   `card.geometry()`，布局一变（换页/resize/内容撑开）立即收尾成最终形态，
   避免快照与真实卡片错位；
6. 收尾：撤 overlay、恢复卡片可见、恢复卡片阴影（blur 60，降级机器 30）。

### 3.3 实测（offscreen；1600×900@1.0 / 2560×1440@1.5 / 2560×1440@2.0）

| 口径 | @1.0 | @1.5 | @2.0 |
| --- | --- | --- | --- |
| 快照区域 | 894×353 | 1341×530 | 1788×706 |
| 构建一次 | 1.38ms | 3.23ms | 5.03ms |
| overlay 每帧（真实 200ms 淡入 13 帧） | 0.08ms | 0.91ms | 0.24ms |
| 对照：卡片 `grab()` 每帧 | 1.28ms | 2.99ms | 4.95ms |
| 对照：卡片 `render()` 每帧 | 1.53ms | 3.38ms | 5.32ms |

像素等价（numpy 逐像素）：`t=1.0` 快照合成 vs 参考（遮罩+卡片）**平均通道差
0.344 / 0.304 / 0.245**、最大 45（差异集中在抗锯齿与阴影边缘）；`t=0.5` 快照合成
vs 卡片 effect 50% **平均差 0.173 / 0.147 / 0.130**、最大 13~15 ⇒ 视觉等价。

### 3.4 模式解析（`resolve_dialog_fade_mode`）

| 条件 | 结果 | 说明 |
| --- | --- | --- |
| `is_bigscreen_mode()` | `direct` | 大屏性能模式是用户显式要「最强降级」，压过一切实现偏好 |
| 超阈值 + 显式 `snapshot` | `snapshot` | |
| 超阈值 + `auto`（默认） | `snapshot` | item2 本意：降级机器也保留淡入 |
| 超阈值 + 显式 `card`/`opacity`/`direct` | `direct` | 降级是安全网，优先于实现选择（既有回归契约） |
| 未超阈值 + 非 auto | 原样返回 | |
| 未超阈值 + `auto` | `card` | 2026-09-25 的 P1-1 行为 |

要在超阈值机器上强制某种实现，正规做法是**把阈值显式关掉**
（`perf_dpi_degrade_pixels=0`），而不是在降级分支里翻花样。

## 四、踩坑记录（都是只有写测试/真机才暴露得出来的）

1. **「对话框自身带 graphics effect」时 `render()`/`grab()` 会丢全部子控件。**
   症状是整图 alpha 全 0（不是「卡片透明」，也不是「render 不可用」）。
   起因是 qfw 原生 `showEvent` 装的 200ms 整窗 opacity effect ——
   `processEvents()` 不会推进 200ms 定时器，所以 effect 一直挂着。
   **推论：任何「先渲染再判定」的逻辑（快照、像素回归、探针）都必须先确认
   `dlg.graphicsEffect() is None`。** 快照分支在构建前显式
   `setGraphicsEffect(None)`，就是在守这条。
2. **`QRegion` 属于 `PySide6.QtGui`，不属于 `QtCore`。**
   首版写进 `QtCore` 的 import 行 → `ImportError` 被构建函数的
   `except Exception` 吞掉 → **快照淡入从未真正生效过**（表现只是「超阈值机器
   还是没动画」）。写回归用例时才暴露。教训：失败安全的 `except` 必须留下
   可观测痕迹，否则它同时也是「故障隐身衣」。
3. **裸 `MaskDialogBase` 的卡片本身是透明的**（qfw 只有对话框子类才给卡片上色）。
   快照构建按设计拒绝这种卡片 —— 这是失败安全的**正常表现**，不是 bug。
   测试里要么用 `MessageBox` 这类真卡片，要么给卡片铺不透明底
   （`setAutoFillBackground(True)` + palette Window=#ffffff，比 `setStyleSheet` 稳，
   不受 qfw 应用样式表影响）。
4. **显式配置被自适应盖掉**：`get_effective_degrade_pixels()` 里「先读配置再判
   explicit」的顺序不能反（见 §2.4）。
5. **Qt `stop()` 不发 `finished`**：`setCurrentTime(duration)` 才能在测试里同步模拟
   自然播完（2026-09-25 已知，本次继续沿用）。

## 五、misc1 / misc2

**misc1（清理）**：`patch_table_scroll_blit` 尾部原先把
`TableBase.__init__` / `QTableView.updateGeometries` 各赋值两遍（后者覆盖前者，
行为幂等）。已合并为一份赋值，保留 `TableBase._perf_blit_patched` 守卫。

**misc2（可观测性）**：位块搬移取不到底色时是**故意静默**的（失败安全），
代价是「我这张表现在到底走没走位块搬移」无人能答。现在：

- 每张表记一个状态：`applied` 已生效（位块搬移）/ `no_bg` 未取到底色 /
  `hidden` 表格·窗口未显示 / `off` 加速已关闭；**只在状态转移时写一行日志**，
  避免重布局刷屏；
- `table_blit_status()` 遍历当前存活表格汇总，判定以**运行期事实**为准
  （viewport 的 `WA_OpaquePaintEvent` + 标定出的底色），不看记账字段 ——
  任何绕过 `apply_table_blit` 的路径都会被算出来；
- `table_blit_status_text()` 输出一行中文（`已生效 3/5 张，未取到底色 2 张`
  + 「表格四周需有 ≥6px 纯色间隙，有遮挡/浮动面板压边则不生效」的排查提示）；
- 两个 UI 入口：性能选项对话框顶部状态行（`main_window/ui_mixin.py`）与
  设置中心「渲染加速状态」按钮（`main_window/hub_pages.py`，点开实时读取，
  因为命中张数随打开的页面变化）。
