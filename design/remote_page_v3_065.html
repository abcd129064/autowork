一期已落地：visitor 热重载 + 端口漂移修复（2026-09-21） P0 设备在线感知 / 连接预检P1 优雅停止 / 连接质量 / 球桌页联动 三期再议：升级 frp 解锁 clients / v2 / store
本稿所有功能仅用 frps 0.65 现有 v1 API + 本机 frpc 0.66 admin即可实现，不依赖任何 0.66+ 新增端点；升级 frp 整体推迟到三期。
为什么锁定 0.65 完全够用（源码逐行核对，非推测）： ① 设备在线判定的权威数据源是 frps GET /api/proxy/xtcp —— 0.65 起每条 proxy 就自带 status:"online|offline" + curConns + lastStartTime + todayTrafficIn/Out（v0.65.0 server/dashboard_api.go L204-207/L255/L260），无需 0.67 的 /api/clients。
② 优雅停止 POST /api/stop 在 frpc 0.65/0.66 均已提供（本机实测 200），零版本依赖。
③ 连接质量（visitor RTT）任何版本 admin 都取不到（frpc /api/status 只列提供端 proxy，纯 visitor 端返回 {}；frps 也看不见 visitor 侧流量）——所以质量必须本地 TCP 探测 bindPort，与版本无关，0.65 反而是正确方案。
结论：把 P0/P1 全建在 0.65 能力上是零妥协的正解，而非降级。被推迟到三期的只是"锦上添花"（见文末能力矩阵）。
