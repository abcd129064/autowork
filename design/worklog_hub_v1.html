模块结构（沿用 windows/<module>/ 子包规范） 
windows/worklog/
├── __init__.py          # re-export shim（兼容旧 import 路径）
├── hub.py               # WorkLogHub（Pivot 容器，五页签）
├── records/page.py      # 页签1 记录量化
├── timeline/page.py     # 页签2 时间轴
├── mindmap/page.py      # 页签3 思维导图
├── stats/page.py        # 页签4 统计汇总
├── members/page.py      # 页签5 成员与分类
└── dialogs.py           # EditWorklogDialog（含连续录入）
database/worklog_db.py    # 数据访问层（thread-local 连接先例）
database/schema.py        # worklog_records / worklog_members DDL 收敛于此
数据模型与双后端
worklog_records：id · work_date · member_id · title · project · category · hours(REAL) · progress(INT) · status · note · created_at · updated_at · deleted(软删除=1，先例与运维表一致)
worklog_members：id · name · alias · active · sort

⚠️ SQLite 侧 _ensure_initialized 自动迁移； MySQL 侧需手动 ALTER TABLE（挂账给用户，双后端行为不一致是既有红线）· DDL 收敛进 schema.py（8 张核心表治理目标的延续）· 删除一律软删除；统计查询自动过滤 deleted=1
