本画布与落地实现的四处差异（画布保留原样作为设计过程记录，实现以此条为准）：
  • 每行一条进度条 → 「进度」文字列 + 页底一条全局进度条。 TableWidget 里塞 setCellWidget 进度条，滚动时要为每行维护一个控件； 20 行清单就是 20 个 ProgressBar，刷新一次要重排 20 次。 批量是顺序跑的，同一时刻只有一条在动，全局那一条足够表达；行内改为 63% · 1.2x 文字，由 refresh_row() 统一刷。
  • 每行挂「放大2x 预计很慢」黄标 → 任务页顶部一条全局 lbl_warn。 预警只由参数决定，与是哪一行无关；逐行挂会在 20 行上重复 20 遍同一句话。
  • 「暂停」与「并发」未实现。ffmpeg 子进程没有可靠的暂停语义；并发多路会同时抢 CPU/GPU 与磁盘带宽，总时长不降反升，进度语义也变复杂。详见文末「本次明确不做」。
  • 「导出命令行」→「复制命令行」。用户拿到命令是为了粘贴去手跑，落文件反而多一步。

画布控件 → 落地控件的对应关系（下面几张画布通用，以此条为准）：
  • 分段按钮（画布里 .seg 那三处：倍率/指定高度、CRF/目标体积、跳过/覆盖/加序号） → qfluentwidgets ComboBox。 SegmentedWidget 在本项目的 qfw 1.11.2 里是存在的，换掉它是取舍不是被迫： 这三处都是「选一个模式、联动置灰另一组控件」，ComboBox 的 userData 正好承载模式键，且与本页其它十几处下拉（算法/编码器/容器/输出模式）形态统一； 分段按钮按文字自适应宽度，标签一变长就把整行顶宽；下拉是固定宽度，不受标签长度影响。 补记：本轮已把所有下拉标签精简成纯名称（如「目标体积」而非「目标体积（两遍编码）」）， 顶宽这一条不再是现实压力，形态统一与 userData 承载模式键这两条才是留下来的理由。 注意 qfw 的 ComboBox 是 QPushButton 不是 QComboBox， addItem 的 userData 必须用关键字传（第二个位置参数是图标）， 且没有 view()/model()。
  • 「存为我的预设」未实现。只保留内置 6 档 + 参数集整体持久化，理由见文末「本次明确不做」。
  • 开关 → SwitchButton，滑块 → Slider + CompactSpinBox 配对。 滑块只给整数刻度，小数精度靠旁边的 spin 输入。
  • 锐化卡多一行 lbl_sharpen_hint「当前生效：…」。 三种算法各有不同的生效字段（cas 只看 sharpen_amount， unsharp 只看 usm_*，unsharp+cas 两组都看）， 没有这行提示，用户拖一个当前算法根本不读的滑块时界面上没有任何东西解释它为什么没效果。 判定必须由 "unsharp" in algo 与 "cas" in algo 两个标志位组合出来—— 只按「字符串里有没有 cas」判，两级算法会被说成只有 cas 生效。
  • 文案口径（2026-11-08 定稿，此后新增控件照此写）。 选项标签只留名称：hqdn3d、libx264、标准增强、 目标体积，不带任何括号说明。 散文式说明只去括号、信息一条不删：hint 行、卡片副标题、info/warning、tooltip、 MessageBox、日志行里的括号旁白一律改写成正常句子，或用 · / — 分隔； 状态类后缀也用 ·，如 libx264 · 不可用、○ hevc_nvenc · 未试编。 保留括号的只有两类：正则分组，以及 Qt 文件对话框强制的 名称 (*.ext) 过滤器格式。
    代价要写清楚：画布里那几行 备选：nlmeans（质量高、极慢）… 从未落地——下拉本身已经枚举了全部选项，再列一遍是重复。而标签精简之后， 各算法/编码器的「快慢与质量代价」在界面上不再出现，这是明确取舍不是遗漏。 要找回这类信息就写成卡里的 _hint 行，不要塞回标签的括号里。 目前仍在界面上承担解释职责的是三处动态文案：滤镜页 lbl_sharpen_hint「当前生效：…」、 编码页 lbl_enc_state（按真编结果给 CRF/CQ 区间建议）、 任务页 lbl_cost「预估：…」。

指标明细

VMAF 需两侧同分辨率；输出被放大时会先把源 lanczos 放大到同尺寸再比，并标注口径
# VMAF（源分辨率与输出一致，无需预缩放）
ffmpeg -i out.mp4 -i src.mp4 -lavfi "[0:v][1:v]libvmaf=log_fmt=json:log_path=vmaf.json" -f null -
# 输出被放大到 2160p 时，先把参考源放大到同尺寸，否则 libvmaf 直接报错
ffmpeg -i out.mp4 -i src.mp4 -lavfi "[1:v]scale=3840:2160:flags=lanczos[ref];[0:v][ref]libvmaf=..." -f null -
# PSNR / SSIM（ffmpeg 内建，不依赖 libvmaf）
ffmpeg -i out.mp4 -i src.mp4 -lavfi "[0:v][1:v]psnr;[0:v][1:v]ssim" -f null -
口径提醒（会显示在页面上）：锐化类滤镜会降低 VMAF/PSNR —— 因为它们改变了像素、 偏离了参考源，而这类指标衡量的是「与源的接近程度」，不是「好不好看」。 所以本页把客观分与主观抽帧并排展示，不把 VMAF 当唯一结论。

滤镜预设 → -vf 串 引擎层 PRESETS 的实际取值
预设-vf 值适用 / 代价
关闭format=yuv420p只换编码器或压体积，画质不动。最快。
轻度修复hqdn3d=1:1:4:4,cas=0.4,eq=contrast=1.02:saturation=1.03,format=yuv420p源本身干净，只想去压缩块效应。
标准增强hqdn3d=1.5:1.5:6:6,cas=0.8,eq=contrast=1.04:saturation=1.06,format=yuv420p默认值，也是推荐档。台球录像通用。
强锐化hqdn3d=1:1:4:4,unsharp=5:5:1:5:5:0.0,cas=1,eq=contrast=1.05,format=yuv420p糊片、失焦。易出白边，慎用于已清晰的源。
老片修复atadenoise=0a=0.02:0b=0.04:s=80,hqdn3d=2:2:8:8,cas=0.6,eq=contrast=1.08:brightness=0.02:saturation=1.08,format=yuv420p强噪点、偏灰的老录像。两级去噪串联，慢。
动漫 / 线条hqdn3d=2:2:6:6,cas=1,eq=contrast=1.06:saturation=1.15,format=yuv420p色块分明、线条锐利的内容。
上表是 build_filter_chain(apply_preset(default_params(), k)) 的逐字输出（落地后回填）。 两处与直觉不同：(1) _fnum() 会削掉尾随 .0，所以滑块上的 1.0 落到串里是 1；(2) eq 的参数顺序由 _eq_filter() 固定为 contrast → brightness → saturation → gamma，不跟随界面控件的排列顺序。 atadenoise 用具名参数 0a/0b/s（阈值由 denoise_luma 换算而来）， 不用位置参数——ffmpeg 版本间位置参数含义变过。
以下为叠加项，按固定顺序插入到预设串中（不是独立预设）： 放大 → 在去噪之后插入 scale=-2:H:flags=lanczos； 补帧 → 在链尾（format 之前）追加 minterpolate=fps=N:mi_mode=mci:mc_mode=aobmc:me_mode=bidir:vsbmc=1。 format=yuv420p 永远置于链尾，保证播放器兼容。

已识别的风险

  • 图标枚举版本约束：本项目 qfluentwidgets 的 FluentIcon 无 GAME_OPTIONS 等成员。 本设计稿选用的是已核对存在于当前安装版本的成员： MOVIE / VIDEO / FILTER / SPEED_HIGH / COMMAND_PROMPT / PIE_SINGLE / FIT_PAGE。 实施时若报 AttributeError，从上述清单里换，不要新造名字。
    落地补充：另有一批成员同样不可用——STOP / PICTURE / PICTURE_TILE / CLEAR / CROP / SHARING / HIGHLIGHT / ALIGN_CENTER / COLOR / ERASE / VIEW_ALL / BULLETED_LIST / TILE / MOSAIC / EFFECT / MAGIC， 以及 ElevatedPushButton 这个类本身。实际用到的是 BRUSH（工具页页签，MOVIE 被「视频修复」占了）、 VIDEO / FILTER / SAVE_AS / COMMAND_PROMPT / PIE_SINGLE（五子页导航）。 冒烟第 5 节会用主窗口的真实映射建弹出窗，图标名写错会在那一节就炸，不必等用户点。
  • 嵌套 PivotPage 的按钮重叠：外层 ToolHub 的 btn_popout 是浮动定位在页面右上角的 （pivot_page._reposition_popout_btn，y≈10）。内层若也浮动，两颗在纵向上只差几像素，窗口一窄就叠住。 解决办法是 _inline_popout() 把内层那颗搬进 Pivot 行布局（落到 y≈44）。
    落地已量化自证：冒烟 2b 节真构造一层 ToolHub，把两颗按钮 mapTo 到同一坐标系， 在 1500/1100/900 三种宽度下均不重叠（外层 y=10~40，内层 y=44~76）。 核对时必须先确认顶层 isVisible()：ToolHub(win) 的构造参数同时是宿主窗口 和 Qt 父对象，父不 show 则子树布局根本不跑，按钮停在 100×30 初值上， 而 isVisibleTo() 仍然返回 True——量出来的「不重叠」是假通过。
  • 子进程僵尸：PivotPage.detach_workers() 只调 requestInterruption() 不 wait()。 Worker 必须在收到 interrupt 后主动终止 ffmpeg 子进程，否则关窗口后 ffmpeg 仍在后台跑满 CPU。
    落地发现的既有缺陷（不属本功能，未修，已上报）：PivotPage.detach_workers() 会扫 dir(page) 里所有以 _worker 结尾的属性，而 NewLogWork._release_upload_worker、 VideoRepairWork._release_repair_worker 是方法，名字正好撞后缀； _stop() 只捕 (RuntimeError, TypeError)，于是抛 AttributeError: 'function' object has no attribute 'requestInterruption'。 两处生产调用点都用 except Exception: pass 吞掉了，所以不崩， 但扫描会在第 4 页中断——排在其后的工具页 worker 在弹出面板关闭时不会被中断。 本功能不受影响：四个 worker 已在 shutdown.py 第 7b 步显式登记（注册点 H）。
  • 耗时预期管理：放大 2x + slow preset 在 1080p 源上约 0.3x 实时，18 分钟视频要跑 1 小时。 设计稿原打算给「放大 ≥ 2x」或「补帧开启」的每一行挂黄色预警标签。 落地改为任务页顶部一条全局 lbl_warn：预警只由参数决定，与是哪一行无关， 逐行挂标签会在 20 行的清单上重复 20 遍同样的话，而且行是复用的（refresh_row）容易残留。
  • 不自动装依赖：ffmpeg 缺失时只提示、只给路径入口，不触发任何下载安装 （AGENTS.md §3.2 禁止擅自安装第三方包）。
  • 历史与配置写入：全部经 core.app_settings 门面，不直接读写 config/ 下文件。
  • 编码器探测失败的呈现：qfluentwidgets 的 ComboBox 是 QPushButton 而不是 QComboBox，没有 view()/model()，也没有单项 tooltip。 置灰只能走它自己的 setItemEnabled(i, bool)，失败原因统一报在下方 lbl_enc_state。 探测失败只置灰不改选择：用户挑的编码器在这台机器上跑不通时，params 里仍是它， 直接开跑会在第一个文件上失败——所以 on_env_ready 里额外弹一条 warning 让他自己去换。
