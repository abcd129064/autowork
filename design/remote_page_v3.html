二期主线：一期解决的是「隧道建得快、不断线」；二期解决「建之前知道值不值得建、建之后知道质量如何、停的时候不伤身」。 三个新增感知面：① 设备在线感知——frps 权威在线名单（snk 无 xtcp proxy = 设备必离线，直接提示，不盲等 1.8s+ 打洞超时）； ② 连接质量——本地 bindPort 全链路 TCP 探测 RTT/成功率（XTCP 直连穿透后 connect≈端到端握手时延，是用户体感的忠实指标）； ③ 本机 frpc 管理通道——admin API 升级为受管面：健康探活、POST /api/stop 优雅停止替代 kill 强杀。
关键事实（源码核验）：生产 frps 0.65 v1 API 提供 /api/proxy/{type}（含 xtcp proxy 名单，批量一次拿全）、/api/clients、/api/traffic/{name}； 本机 frpc 0.66.0 admin 实测具备 reload/stop/status/config（全 200）——POST /api/stop 优雅停止 0.65/0.66 就能用，P1 不受版本限制；但 /api/status 只列「提供端 proxy」，纯 visitor 端恒返回 {}，连接质量仍须本地探测（与版本无关）。真正的版本墙在：frpc /api/store/visitors*（HTTP 直增删免重写 TOML）需 0.68+；frps /api/clients 需 0.67+、/api/v2/* 需 0.70+——但 P0 在线感知改用 0.65 即有的 /api/proxy/xtcp，故二期 P0/P1 全部可在 0.65 生产落地。

# 新增 core/frps_admin.py —— frps 感知客户端（只读，零写操作，纯查询零风险）
class FrpsAdminClient(QObject):
    proxies_changed = Signal(object)        # {snk: {"online":bool,"lastSeen":ts}} —— xtcp proxy 名单按 snk 归一
    channel_state   = Signal(str)           # "ok" | "unreachable" | "unauthorized" | "unconfigured"
    def refresh(self):                      # GET {base}/api/proxy/xtcp（0.65 v1，批量一次）→ 解析 name 列表
    def online_set(self) -> set[str]|None   # 缓存优先（<30s 新鲜），None=感知不可用，调用方必须按未知处理
    def traffic(self, name) -> tuple|None   # GET /api/traffic/{name}（P2 预留，中继 proxy 才可见）
    # 熔断：连续 3 次失败 → 60s 静默降级为 unconfigured 行为（不重试风暴、不刷日志）

# 新增 core/visitor_probe.py —— RTT 质量调度（探测模型：connect 本地 bindPort）
class VisitorProber(QObject):
    sample = Signal(str,int|None)           # (snk, rtt_ms|None超时)；环形缓冲 120 点/隧道
    verdict = Signal(str,str)               # ok | degraded(连续超时) —— 驱动总览状态列「异常」
    # QTimer 30s 串行轮询运行中隧道；hideEvent 暂停、showEvent 立即刷一次；单次超时 800ms
