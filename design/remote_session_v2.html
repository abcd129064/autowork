1信息架构：一级导航 + 四个二级页 「远程会话」回归一级导航（本期已移除）；页内 Pivot 分四页：会话总览 / P2P 访客 / 连接诊断 / 隧道配置。原 RemoteSessionWindow 独立窗口降层为页内容器，与运维/售后的 Hub 模式一致。
2会话总览 = 表格化会话中心 每行一个 frpc 会话：状态灯 + 流量 + 持续时间实时刷新（复用现有 _p2p_visitors / session_manager 单例）。行内直达终端 / SFTP 文件窗 / RDP，避免往返弹窗。
3原生 HWND 约束的处理 SSH 终端 / RDP 依赖原生窗口句柄，无法真正嵌入 Qt 页——采用「页内启动卡片 + 独立窗口跟随」：点击行内动作弹独立窗口，本页表格保持状态同步（对照一期启动卡片页的过渡方案）。
4连接诊断页迁入 原 ConnDiagPanel 整体迁入第三页（SSH/SFTP 失败记录、归档查询），保留现有 _apply_smooth_mode 平滑滚动开关口径，归全局「性能 → 远程会话表格平滑滚动」。
5隧道配置页 = frpc_xtcp_panel.toml 可视化 只读表格 + 「打开 toml」按钮（复用 _open_config_file），新增/编辑仍走既有对话框，避免两套持久化路径。
6实施顺序建议 ① 会话总览（迁移 session_manager 列表 + 状态轮询）→ ② P2P 访客迁入 → ③ 连接诊断迁入 → ④ 隧道配置可视化。每步独立冒烟 + pytest 回归，不阻塞一期功能。
